## 1. 项目概述

### 1.1 一句话定义

> **VR-Class 是一个"按需开课"的沉浸式 AI 课堂：学生说出今天想学什么，AI 即以老师的身份，在一间虚拟教室里，用板书、图示、动画和讲解，分章节地把这堂课"上"给学生看。**

### 1.2 项目背景与动机

现有的 AI 学习工具大多是**聊天框 + 大段文字**，存在三个问题：

1. **被动阅读，缺乏"被教"的感觉**：用户面对的是一堵文字墙，而不是一位在讲台上演示的老师。信息以文本流出现，认知负荷高、沉浸感弱。
2. **缺乏教学法结构**：模型经常"一股脑倒信息"，没有"导入 → 是什么 → 为什么 → 怎么做 → 演示 → 检验 → 小结"的教学节奏。
3. **视觉表达弱**：很多学科（数学、物理、生物、工程、编程）天然依赖图、公式、动画、分步演示。纯文字损失巨大。

VR-Class 的机会，是把 LLM 的内容生成能力，从"聊天"升级为"**一位会板书、会画图、会演示、会按教学节奏讲课的老师**"。

### 1.3 产品愿景

**短期**：在浏览器里复刻"一对一私教课"的体验——你坐在虚拟教室里，看着老师把任意一个主题，一笔一画、分章节地讲明白。

**长期**：成为"任意主题、随到随学"的私人沉浸式课堂，并可平滑升级到 VR 头显的全沉浸空间课堂（WebXR / 头显原生）。

**北极星愿景**：让"我想学 X"到"我真的看懂了 X"之间的距离，缩短为一次开口。

### 1.4 名词解释

| 术语 | 含义 |
| --- | --- |
| 一堂课 / Lesson | 针对一个主题生成的完整授课单元，含多个章节。 |
| 章节 / Chapter | 课程的逻辑分段，默认遵循"是什么 / 为什么 / 怎么做 / 演示 / 检验 / 小结"。 |
| 演示脚本 / Lesson Script | AI 生成的、可被前端"播放"的结构化数据：由一连串「场景（Scene）」组成，每个场景含讲解词 + 视觉指令 + 时序。**这是连接 AI 与画面的核心数据契约。** |
| 场景 / Scene | 演示脚本的最小播放单位：一段讲解 + 一块视觉内容（板书/图/公式/动画/代码…）。 |
| 智能板书 / Smart Board | 教室中央承载视觉内容的"黑板/白板"区域，能逐步渲染文字、图示、公式、动画、代码、图片。 |
| 老师形象 / Tutor Avatar | 授课者的虚拟形象（语音 + 可选的 2D/3D 形象）。 |
| 数字人 / Digital Human | 带口型同步与肢体动作的 3D 虚拟人方案（进阶可选）。 |

## 2. 产品定位

### 2.1 目标用户

| 用户群 | 典型诉求 | 优先级 |
| --- | --- | --- |
| **自学者 / 终身学习者**（核心） | 临时想搞懂某个概念、某项技能，希望"有人讲给我听并演示" | P0 |
| **学生（K12 / 大学）** | 预习、复习、补差，按学科或考点点播一堂课 | P0 |
| **职场/技能学习者** | 学某个工具、框架、领域知识，需要分步演示 | P1 |
| **教育内容创作者 / 老师** | 快速生成可视化课件、讲解视频的雏形 | P2（后期） |

**首发聚焦人群**：成年自学者 + 高年级学生（自驱、能清晰说出"我要学什么"、对沉浸式体验敏感）。

### 2.2 使用场景

- "我明天面试要懂**一致性哈希**，给我上一堂课。"
- "讲讲**光合作用**，我生物要考。"
- "我想搞懂**微积分里的极限**到底在说什么。"
- "教我用 **Python 的装饰器**。"
- "给我讲一节**明朝为什么会灭亡**。"

共同点：**用户用一句自然语言点题，期望得到一堂"被演示出来"的完整课，而不是一段文字回答。**

### 2.3 价值主张与差异化

| 对比对象 | 它们的形态 | VR-Class 的差异 |
| --- | --- | --- |
| ChatGPT / 通用聊天 AI | 文字问答 | **视觉优先 + 老师在场 + 教学法结构**，是"上课"不是"查资料" |
| 录播网课（B站/慕课） | 固定、人工制作、非按需 | **任意主题、即时生成、千人千面** |
| PPT / 文档 | 静态、需自己读 | **动态演示 + 语音讲解 + 互动追问** |
| AI 出题/刷题 App | 练习驱动 | VR-Class 先"讲懂"，练习是其中一环 |

**三条设计原则（产品的灵魂）**：

1. **视觉优先（Visual-First）**：默认用图、公式、动画、分步板书表达，文字是讲解词不是主体。能画就不写，能演示就不讲。
2. **老师在场（Tutor Presence）**：有一位稳定人设的老师，"表演"这堂课——他会写板书、会指、会圈重点、会停下来问"懂了吗"。
3. **教学法结构（Pedagogy-Structured）**：每堂课遵循清晰的认知节奏（是什么 → 为什么 → 怎么做 → 演示 → 检验 → 小结），而不是信息倾倒。

### 2.4 产品形态决策（重要）

> **推荐：采用"渐进增强"路线。** MVP 先做**网页版虚拟教室**（屏幕沉浸，无需头显，触达成本最低），但把"演示脚本 / 内容引擎"做成**平台无关**的——未来可在其上叠加 **WebXR / 头显原生**客户端，实现真 VR 全沉浸，而内容生成层不需要重写。

理由：真 VR（头显）虽然沉浸感最强，但**设备渗透率低、开发成本高、内容生产链路重**，不适合验证产品价值。先用网页验证"AI 现场授课"这件事成不成立，再决定是否上头显。详见第 12 章待确认决策 D1。

## 3. 核心概念与体验流程

### 3.1 核心使用闭环（用户旅程）

```
进入虚拟教室
      │
      ▼
说出今天要学什么（文字/语音）  ──►  AI 理解意图（学科/主题/深度/已知基础）
      │
      ▼
AI 现场规划课程大纲（章节列表）  ──►  学生可微调（更浅/更深/换角度）
      │
      ▼
┌─────────────── 逐章节授课（核心体验）───────────────┐
│  老师讲解（语音）+ 智能板书同步演示（图/公式/动画/代码）│
│  学生可随时：暂停 / 提问 / "再讲一遍" / "举个例子" / 跳过 │
└────────────────────────────────────────────────────┘
      │
      ▼
随堂检验（小测/口头提问）  ──►  根据掌握情况补讲
      │
      ▼
小结 + 课程存档（可回放、可继续深入）
```

### 3.2 一堂课的标准结构

默认章节模板（可按学科/主题自适应增减）：

| # | 章节 | 教学意图 | 典型视觉 |
| --- | --- | --- | --- |
| 1 | **导入 / 钩子** | 用一个问题、现象或类比勾起兴趣 | 一张引发好奇的图 / 一个反直觉的问题 |
| 2 | **是什么（What）** | 给出清晰定义与边界 | 关键词板书、概念图、思维导图 |
| 3 | **为什么（Why）** | 讲动机、意义、它解决什么问题 | 对比图、"没有它会怎样"的反例 |
| 4 | **怎么做 / 原理（How）** | 拆解机制、步骤、推导 | 分步动画、流程图、公式逐步展开 |
| 5 | **演示 / 例子（Demo）** | 用具体实例走一遍 | 代码运行、习题演算、案例拆解 |
| 6 | **检验（Check）** | 确认是否真的懂了 | 随堂小测、追问、错因分析 |
| 7 | **小结 + 延伸** | 收束重点、指引下一步 | 一页式总结图、延伸主题清单 |

> 不同学科会自适应：编程课强化"演示/代码"，历史课强化"叙事/时间线"，数学课强化"推导动画"。

### 3.3 示例：一堂《光合作用》课的演示脚本（节选）

为了让"演示脚本"具体可感，给出一个片段（数据结构详见 5.3）：

```jsonc
{
  "topic": "光合作用",
  "level": "初中",
  "chapters": [
    {
      "id": "what",
      "title": "光合作用是什么",
      "scenes": [
        {
          "narration": "想象一片叶子，它其实是一座小小的太阳能工厂。",
          "visual": { "type": "image", "prompt": "一片绿叶，阳光照射，卡通示意" },
          "board_action": "fade_in"
        },
        {
          "narration": "它把阳光、水和二氧化碳，变成糖和氧气。我们把这个过程叫光合作用。",
          "visual": {
            "type": "diagram",
            "format": "mermaid",
            "content": "graph LR; 阳光-->叶绿体; 水-->叶绿体; CO2-->叶绿体; 叶绿体-->糖; 叶绿体-->氧气"
          },
          "board_action": "draw_step_by_step",
          "highlight": ["叶绿体"]
        },
        {
          "narration": "用一个式子表示就是——",
          "visual": { "type": "formula", "latex": "6CO_2 + 6H_2O \\xrightarrow{光能} C_6H_{12}O_6 + 6O_2" },
          "board_action": "write_formula"
        }
      ]
    }
    // ... why / how / demo / check / summary 各章节
  ]
}
```

前端拿到这段脚本，就能"播放"出：老师说话 → 板书上叶子淡入 → 流程图一步步画出来并高亮"叶绿体" → 公式逐项写出。**这就是"视觉化授课"的技术本质：把课变成一段可播放、可互动的结构化脚本。**

| 编号 | 功能 | 描述 | 优先级 |
| --- | --- | --- | --- |
| F1 | 进入虚拟教室 | 加载教室场景、老师形象、入座视角 | Must (MVP) |
| F2 | 主题输入与意图理解 | 自然语言点题，解析学科/主题/深度/基础 | Must (MVP) |
| F3 | 课程大纲规划 | 生成可调整的章节大纲 | Must (MVP) |

| F9 | 个性化设置 | 难度、讲解风格、语速、学科偏好 | Should |

| F11 | 3D 老师/数字人 | 口型同步、肢体动作 | Could (v1.0) |
| F12 | 语音提问（ASR） | 学生开口提问 | Could |
| F13 | VR / WebXR 客户端 | 头显全沉浸课堂 | Won't (本期) / 未来 |

### 4.2 详细功能说明

#### F1 · 进入虚拟教室
- 用户打开应用，进入一间虚拟教室：**学生第一人称视角**，正前方是老师 + 智能板书。
- MVP 可用"插画风静态教室背景 + 板书区 + 老师立绘/头像"实现，不必 3D。
- 提供"开始上课"入口与历史课程入口。

#### F2 · 主题输入与意图理解
- 输入方式：文本框（MVP）/ 语音（后期）。
- 系统需解析：**学科领域、具体主题、目标深度（科普/应试/专业）、学生已有基础、特殊诉求（如"为面试""为考试"）**。
- 信息不足时，老师**最多追问 1–2 个澄清问题**（如"你是想从零开始，还是已经懂基础？"），避免打断沉浸感。

#### F3 · 课程大纲规划
- AI 生成章节大纲并**先展示给学生**（如板书上列出今天要讲的几点）。
- 学生可一句话调整："太深了，讲浅一点""我已经懂是什么了，直接讲怎么做""多讲点例子"。
- 大纲确认后进入授课。

#### F4 · 可视化授课（**核心功能**）
- 按章节顺序播放演示脚本（见第 5、6 章）。
- 每个场景：老师讲解（语音）与板书视觉**同步呈现**；板书内容**逐步出现**（模拟老师边讲边写边画），而非整屏闪现。
- 支持的视觉类型见 5.2。
- 章节之间有清晰的过渡（"这一节我们讲完了，接下来看为什么"）。
- 提供进度指示（当前第几章、整体进度）。

#### F5 · 讲解语音（TTS）
- 老师讲解词通过 TTS 合成语音，**与板书动作时序对齐**。
- 可调语速；提供字幕（讲解词同步显示，便于无声环境/可访问性）。
- 老师人设需有稳定音色与语气（亲切、有耐心、会停顿）。

#### F6 · 学生互动
- **播放控制**：暂停 / 继续 / 上一章 / 下一章 / 跳过当前章。
- **追问**：学生随时提问，老师在**当前上下文**中回答（MVP 用文字提问 + 文字/板书作答；后期支持语音 + 临时插入演示场景）。
- **学习指令**：常用快捷意图——"再讲一遍""换个说法""举个例子""太快了""太简单了，深入点"。
- 追问结束后，能**回到原授课进度**继续。

#### F7 · 随堂检验
- 在检验章节，老师出 1–3 道小题（选择/填空/简答）或口头追问。
- 根据学生作答**判断掌握度**：答对则推进，答错则针对性补讲（讲解错因，换角度再说一遍）。

#### F8 · 课程存档与回放
- 已生成的课程可保存（演示脚本 + 音频缓存），支持**重新播放**、**断点续学**、**继续深入**（"在这堂课基础上再讲进阶部分"）。

#### F9 · 个性化设置
- 难度档位（科普 / 应试 / 专业）、讲解风格（严谨 / 风趣 / 极简）、语速、是否显示字幕、学科偏好。
- 记住用户偏好，跨课沿用。

## 5. 视觉呈现系统（核心模块详述）

> 这是本产品区别于"聊天 AI"的关键。本章定义"画面由什么构成、能展示什么、用什么数据驱动"。

### 5.1 画面分层

```
┌──────────────────────────────────────────────┐
│  ① 场景层 / 教室环境（背景、课桌、氛围）          │
│   ┌────────────────────────────────────────┐  │
│   │  ② 智能板书（教学内容主舞台）             │  │
│   │     文字 / 图示 / 公式 / 动画 / 代码 / 图片 │  │
│   └────────────────────────────────────────┘  │
│  ③ 老师形象层（立绘/头像/3D，含讲解与指示动作）   │
│  ④ 标注层（高亮、圈点、箭头、聚光）              │
│  ⑤ 字幕 / 控制条 / 进度（HUD）                  │
└──────────────────────────────────────────────┘
   ⑥ 语音层（讲解 TTS，与②③时序对齐）
```

### 5.2 智能板书：支持的可视化类型（MVP 必备 ★）

| 视觉类型 | 用途 | 实现技术（建议） | MVP |
| --- | --- | --- | --- |
| 文字板书 / 要点 | 定义、关键词、列表 | 富文本 + 逐字/逐行出现动画 | ★ |
| 数学公式 | 推导、定理 | KaTeX / MathJax（LaTeX 渲染） | ★ |
| 图示 / 流程图 / 思维导图 | 概念关系、流程、结构 | Mermaid → SVG，分步绘制 | ★ |
| 代码 | 编程教学 | 语法高亮 + 逐行出现 + 可"运行" | ★ |
| 图表 | 数据、函数曲线 | D3 / ECharts / 生成 SVG | ☆ v0.2 |
| 插图 / 配图 | 形象化、情境化 | 图像生成模型 / 图库检索 | ☆ v0.2 |
| 动画 | 过程演示（如波形、反应、算法） | 模板动画 / Manim 类离线渲染 / Lottie | ☆ v0.2+ |
| 标注与指示 | 高亮、圈点、箭头 | 覆盖层（Canvas/SVG），由脚本驱动 | ★（基础版） |

> **关键设计**：所有视觉都由演示脚本里的结构化指令驱动，**逐步呈现**以模拟"老师边讲边写"。这是沉浸感的来源，也是与"贴一张图"的本质区别。

### 5.3 演示脚本（Lesson Script）数据契约

这是 **AI 与前端之间的核心接口**。建议结构：

```jsonc
Lesson {
  topic: string,
  level: string,                 // 科普 / 应试 / 专业
  language: string,
  tutor_persona: string,         // 老师人设 id
  chapters: Chapter[]
}

Chapter {
  id: string,                    // what / why / how / demo / check / summary ...
  title: string,
  scenes: Scene[]
}

Scene {
  narration: string,             // 老师讲解词（同时用于 TTS 与字幕）
  visual: Visual,                // 这一场景的视觉内容
  board_action: enum,            // fade_in / draw_step_by_step / write_formula / type_code / highlight / clear ...
  highlight?: string[],          // 需要高亮/指示的元素
  pause_for_question?: boolean,  // 是否在此停顿，邀请提问
  est_duration_ms?: number       // 预估时长，用于时序对齐
}

Visual =
  | { type: "text",    content: string }
  | { type: "formula", latex: string }
  | { type: "diagram", format: "mermaid"|"svg", content: string }
  | { type: "code",    language: string, content: string, runnable?: boolean }
  | { type: "image",   prompt?: string, url?: string }
  | { type: "chart",   spec: object }
  | { type: "animation", template: string, params: object }
```

> 这个契约让**内容生成（AI）**与**渲染播放（前端）**解耦：AI 只要产出合法脚本，前端就能演。新增视觉类型 = 扩展 `Visual` 联合类型 + 前端加一个渲染器。

### 5.4 老师形象方案选型

| 方案 | 描述 | 成本/复杂度 | 沉浸感 | 建议 |
| --- | --- | --- | --- | --- |
| A. 语音 + 静态立绘/头像 | 老师有形象但不动，靠"说话指示灯"+板书 | 低 | 中 | **MVP 采用** |
| B. 2D 动态形象 | Live2D / Rive，会眨眼、口型、指向板书 | 中 | 较高 | v0.2 |
| C. 3D 数字人 | 口型同步 + 肢体动作 | 高 | 高 | v1.0 评估 |

> 原则：**先把"板书演示 + 讲解"做扎实**，老师形象可后置增强。一个会清晰演示的"声音 + 立绘"，体验已远胜聊天框；过早做 3D 数字人易陷入"恐怖谷"且拖慢核心价值验证。

### 5.5 场景 / 教室方案选型

| 方案 | 描述 | MVP |
| --- | --- | --- |
| 插画风静态教室背景 + 板书区 | 一张有氛围的背景图，聚焦板书 | ★ 采用 |
| 轻 3D / 视差场景 | 有空间感但仍是网页 | v1.0 |
| WebXR / 头显原生 3D 教室 | 真 VR 全沉浸 | 未来 |

## 6. 内容生成管线

### 6.1 流水线总览

```
学生输入
   │
   ▼
[1] 意图理解 ──► 学科/主题/深度/基础/诉求
   │
   ▼
[2] 课程规划（LLM）──► 章节大纲（是什么/为什么/怎么做…）
   │  └─（学生可调整大纲）
   ▼
[3] 逐章内容生成（LLM）──► 每章产出 Scene 序列（讲解词 + 视觉规格）
   │
   ▼
[4] 视觉资产生成 ──► 图示(Mermaid/SVG)、公式(LaTeX)、代码、图片(生成/检索)、动画
   │
   ▼
[5] 讲解语音合成（TTS）──► 每个 Scene 的音频 + 时长
   │
   ▼
[6] 组装为可播放演示脚本（含时序对齐）
   │
   ▼
[7] 前端播放（教室 + 板书 + 老师 + 语音）
   │
   ▼
[8] 互动分支（提问/再讲/检验）──► 临时插入/重排 Scene
```

### 6.2 渐进式生成与播放（降低"首帧延迟"）

**问题**：整堂课全部生成完再播，等待太久，沉浸感差。

**方案**：**流式 / 渐进式**——

1. 先生成并展示大纲（秒级反馈）。
2. **边播边生成**：第 1 章生成完即开始播放，同时后台生成第 2 章；播放速度由 TTS 讲解决定，通常足够掩盖后续章节的生成耗时。
3. 视觉资产里耗时项（如图片/动画）可先用占位/草图，生成完再替换；或对这些项降级为"轻量视觉"。
4. 已生成内容缓存，回放/他人学同主题可命中缓存，降本提速。

### 6.3 教学准确性与防幻觉（高优先级风险）

教错知识比答错问题危害更大。措施：

- **结构化生成 + 自检**：生成后让模型对关键事实/公式/代码做一次"自我校验"通道。
- **可运行验证**：代码类内容尽量在沙箱中实际运行验证；数学推导可做符号/数值校验。
- **可溯源（进阶）**：对事实密集学科（历史、医学等）引入检索增强（RAG），关键结论可给出处。
- **难度/范围约束**：按所选深度档位约束，避免超纲或臆造细节。
- **不确定即坦诚**：模型不确定时，老师应说"这里存在争议/我不确定"，而非编造。
- **用户纠错回路**：学生可标记"这里讲错了"，进入复核与修正。

## 7. 技术架构（建议）

> 本章为落地建议，非强制约束；最终技术选型在立项评审确定。

### 7.1 总体架构

```
┌── 客户端（Web，MVP）────────────────────────┐
│  虚拟教室 UI · 板书渲染器(KaTeX/Mermaid/代码) │
│  老师形象 · 语音播放 · 字幕 · 播放控制 · 提问  │
└───────────────▲───────────────┬─────────────┘
                │ 演示脚本/音频   │ 用户输入/提问
┌───────────────┴───────────────▼─────────────┐
│  编排后端（Orchestration Service）            │
│  意图理解 · 课程规划 · 逐章生成 · 资产生成     │
│  TTS 调度 · 时序组装 · 流式下发 · 缓存          │
└───────┬───────────┬───────────┬─────────────┘
        ▼           ▼           ▼
   LLM(Claude)   TTS 服务   图像/动画生成 · 代码沙箱
        │
   缓存/存储（课程脚本、音频、用户进度、偏好）
```

### 7.2 前端（MVP：Web）

- 框架：React / Next.js（或同类）。
- 板书渲染器（可插拔）：**KaTeX**（公式）、**Mermaid**（图示）、代码高亮（Shiki/Prism）、SVG/Canvas（标注与分步绘制）。
- 演示脚本"播放器"：按 Scene 序列驱动视觉动画与音频，做时序对齐与播放控制。
- 后续可替换/叠加为 **WebXR（Three.js / React-Three-Fiber）** 实现 3D 教室与头显支持，复用同一套演示脚本。

### 7.3 后端与编排

- 一个**编排服务**负责把"学生输入"变成"可播放演示脚本"：调用 LLM 规划与生成、调度视觉资产与 TTS、做时序组装与流式下发。
- 流式下发（SSE / WebSocket）支撑"边播边生成"。
- 缓存层：相同主题/深度的课程脚本与音频可复用。

### 7.4 AI 模型选型

建议采用 **Claude 系列**，按"质量优先 / 速度优先"分层使用：

| 用途 | 诉求 | 选型建议 |
| --- | --- | --- |
| 课程规划、逐章内容与讲解词生成、演示脚本结构化 | **质量、教学法、结构化输出** | Claude Opus / Sonnet（高能力档） |
| 实时追问、轻量交互、意图解析 | **低延迟、低成本** | Claude Haiku（快速档） |
| 事实校验 / 自检通道 | 准确性 | 高能力档 + （进阶）检索增强 |

> 设计上把"模型"做成可配置，便于按成本/质量调档与后续升级。

### 7.5 第三方能力

- **TTS**：高质量、可调语速、支持中文与目标语种、低延迟、可缓存。
- **图像生成 / 图库**：生成配图或检索匹配图（v0.2）。
- **数学/过程动画**：Manim 类离线渲染管线（v0.2+），或模板化轻动画（Lottie）。
- **代码沙箱**：安全执行与验证代码示例。

## 8. 非功能需求

| 维度 | 要求 |
| --- | --- |
| **性能 / 延迟** | 点题后**≤ 3–5 秒**出大纲并开始第 1 章；后续章节靠"边播边生成"无感衔接。 |
| **成本** | 单堂课的 LLM + TTS + 图像生成成本可控、可监控；通过缓存、模型分层、视觉降级控制单位成本。 |
| **准确性** | 教学内容事实/公式/代码正确为硬指标；建立自检与纠错回路（见 6.3）。 |
| **可用性** | 核心操作零学习成本：说出主题即可上课；播放控制直观。 |
| **可访问性** | 全程字幕、可调语速、可调字号、色彩对比达标、键盘可达。 |
| **隐私与安全** | 学习记录与偏好属个人数据，明确存储与使用边界；内容安全过滤（避免不当/有害内容）。 |
| **可扩展性** | 新增学科 = 调整提示与视觉模板，不改架构；新增视觉类型 = 加一个渲染器。 |
| **平台演进** | 演示脚本平台无关，支撑从 Web 平滑扩展到 WebXR / 头显。 |
| **国际化** | 至少中文优先，架构支持多语种讲解与界面。 |

## 9. MVP 范围与迭代路线图

### 9.1 MVP（v0.1）— "一个会演示的网页老师"

**目标**：验证核心假设——"AI 现场把任意主题，用视觉化、有结构的方式讲给我听"是否成立、是否打动人。

**纳入（In）**：
- Web 端虚拟教室（插画背景 + 板书区 + 老师立绘/头像 + 说话指示）。
- 自然语言点题 + 意图理解（必要时 1 个澄清问题）。
- 课程大纲规划，学生可一句话调整深浅。
- 逐章节授课，遵循"是什么/为什么/怎么做/演示/小结"。
- 智能板书：**文字、公式(KaTeX)、图示(Mermaid)、代码** 四类视觉，**逐步呈现** + 基础高亮。
- TTS 讲解 + 同步字幕。
- 播放控制（暂停/继续/上下章）+ **文字追问**（当前上下文作答）。
- 边播边生成（降低首帧延迟）。

**暂不纳入（Out，留待后续）**：
- 图像/动画生成、图表（v0.2）。
- 2D 动态 / 3D 数字人老师（v0.2 / v1.0）。
- 语音提问（v0.2）。
- 随堂检验自动判分与自适应补讲（v0.2）。
- 课程存档/回放体系、学习路径（v0.2+）。
- VR / WebXR 头显（未来）。

**建议首发学科切片**：先打磨 2–3 个视觉收益最大的领域（如**编程、数学/理科、概念解释类**），把"演示"做到惊艳，再横向扩科。

### 9.2 迭代路线图

| 版本 | 主题 | 关键增量 |
| --- | --- | --- |
| **v0.1 MVP** | 会演示的网页老师 | 上述 MVP 范围 |
| **v0.2** | 更丰富的视觉与互动 | 图像/动画/图表生成；随堂检验+自适应补讲；语音提问；课程存档回放 |

## 10. 成功指标

**北极星指标**：**完成并自评"看懂了"的课堂数 / 周**（既要上完，也要真懂）。

| 类别 | 指标 |
| --- | --- |
| 价值 | 课程完成率；随堂检验正确率；"我看懂了"自评比例 |
| 体验 | 点题到开讲的首帧延迟；提问后回到进度的顺畅度；语音/板书同步满意度 |
| 留存 | 次日/7 日回访率；人均周上课数；同一用户的学科广度 |
| 成本 | 单堂课综合成本（LLM+TTS+图像）；缓存命中率 |
| 质量 | 内容纠错率（被学生标记"讲错"的比例）；事实自检通过率 |

## 11. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| **教学内容出错（幻觉）** | 高：误导学习 | 自检通道、代码沙箱验证、关键学科 RAG、用户纠错回路、不确定即坦诚 |
| **生成延迟拖累沉浸感** | 高 | 边播边生成、占位/降级、缓存、模型分层 |
| **单堂课成本过高** | 中高 | 缓存复用、模型按需分档、视觉资产复杂度分级 |
| **"VR/视觉"范围失控** | 中 | 严守渐进增强：先 Web 屏幕沉浸，验证后再上头显/3D |
| **视觉资产质量参差** | 中 | 优先确定性强的视觉（公式/图示/代码），图片/动画作增强而非依赖 |
| **数字人"恐怖谷"** | 中 | 老师形象后置，先把演示讲解做扎实 |
| **学科覆盖参差** | 中 | 首发聚焦高视觉收益学科，逐步扩科并沉淀模板 |
| **互动打断后难回归** | 中 | 设计清晰的"提问—回答—回到进度"状态机 |
